Where the data changes shape

Think of the adapter as a translation desk. It lets old UI code speak to the newer gateway, but translation is not lossless. A field visible in a CG response may be gone by the time it reaches the page.
Design questionCurrent answerConfidence
Can the UI show identity, name, description and logo?Yes; these are preserved, with fallbacks.GO
Can it show provider / builder attribution?Yes, narrowly; the current Preview logic uses it for partner-built tools.GO · narrow
Can it show the real enabled state or real tool count?No. Enabled is defaulted and the count can be an ambiguous allowed-tools length.NO-GO
Can Preview show tool parameter / response schemas?No. The adapter replaces those fields with null.NO-GO
Can it preserve selected tools and “all tools”?Usually, but empty has a special meaning and names are re-encoded.CONDITIONAL

Full field-by-field ledger: docs/initiatives/connectors/connector-gateway-adapter-field-loss.md

Backend questions

Colin McNeil, Vinh Vu and Kapil Duraphe own the backend side of gateway behavior.

When to involve QA

Any change touching both feature-flag paths, connection status, Salesforce behavior, or Preview tool rows.

Rules of thumb

Ask “which path?”

Every data or loading change must work with connector-gateway on and off.

Do not trust compatibility defaults

A value such as enabled: true may exist only to satisfy an older UI contract.

Keep local fields local

Manual configuration and agent-owned state must not be overwritten during provider sync.

Prefer small ownership boundaries

ConnectorsTab is large. Extract orchestration before making a broad visual rewrite.
